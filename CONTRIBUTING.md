# Contributing to ChoiceLab

Thanks for your interest in ChoiceLab. This project values careful research practice, accessible interaction design, and small, reviewable changes.

## Before contributing

Read the relevant material in `docs/` before proposing a research, design, or implementation change. Keep an explicit distinction between:

- research plans and completed research
- design hypotheses and validated findings
- illustrative concepts and implemented functionality

Do not add invented participant details, quotes, observations, survey results, usability findings, or personas. Cite evidence and record its source when adding research-derived material.

## Development guidelines

- Keep the web interface focused on the active project phase.
- Use semantic HTML and preserve keyboard access and visible focus states.
- Do not add financial recommendations, automated decision-making, authentication, account integrations, or analytics without a documented research and design rationale.
- Keep API contracts small, typed, and documented.
- Avoid collecting sensitive financial or personal data during the foundation phase.
- Use plain language. Do not use em dashes in public documentation or interface copy.

## Making a change

1. Create a focused branch.
2. Explain the user, research, or technical reason for the change.
3. Update documentation when a decision affects research framing, requirements, or evaluation.
4. Run the relevant checks before requesting review.
5. Describe validation and any remaining limitations in the pull request.

## Review standards

Reviewers should be able to identify why a change exists, which phase of the project it supports, and whether it presents a claim as evidence or as a question for investigation.
